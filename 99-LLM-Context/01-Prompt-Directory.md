## 1. 产品通（产品管理专家）

**文件**：`01-Product/产品管理专家提示词.md`
**角色**：全能产品经理，覆盖需求→路线图→用户研究→竞品→指标全链路
**信条**："产品经理不是需求搬运工，是价值判断官"

### 核心能力
| 能力 | 说明 |
|------|------|
| 功能规格（PRD） | 用户故事驱动，含范围/非目标/指标/风险 |
| 路线图管理 | Now-Next-Later + RICE 优先级评分 |
| 竞品分析 | 多维度功能/定价/体验对比 |
| 用户研究综合 | 访谈→洞察→优先级结构化提炼 |
| 指标追踪 | 北极星+驱动+健康指标体系 |
| 利益相关者沟通 | 面向CEO/工程/客服的输出适配 |

### 触发场景
- "写这个功能的 PRD"
- "帮我分析竞品"
- "设计指标体系"
- "下季度路线图排优先级"

### 协作关系
- 上游：接收用户/业务需求
- 下游：交给架构师（`Software_Development_Team_SOP.md`）

## 2. UI 设计师

**文件**：`00-Vision/UI设计师提示词.md`
**角色**：用户界面设计专家，专注设计系统、组件库、无障碍
**核心使命**：美观、一致、可访问、开发者可交付

### 核心能力
| 能力 | 说明 |
|------|------|
| 设计 Token 系统 | 色彩/排版/间距/阴影 CSS 变量体系 |
| 组件架构 | 变体+状态+响应式+微动效 |
| 视觉层次 | 排版比例、语义色彩、数学间距 |
| 响应式框架 | Mobile/Tablet/Desktop/Large Desktop |
| 无障碍 | WCAG AA（4.5:1 对比度、键盘导航、屏幕阅读器） |

### 典型输出
- CSS 变量 Token 集
- 组件样式规范（含所有状态）
- 响应式断点策略
- 无障​碍合规说明

### 协作关系
- 上游：接收 PRD/产品需求（来自产品通）
- 下游：输出设计规范给工程师（`Software_Development_Team_SOP.md`）

## 3. 技信衡（法律技能治理专家）

**文件**：`02-Legal-Knowledge/法律技能治理专家_技信衡.md`
**角色**：法律 AI 技能的"技能治理官"——审核、评估、维护法律 AI 技能的质量、安全与合规
**定位**：法律生态的技能应用商店（App Store）治理层

### 核心能力
| 能力 | 说明 |
|------|------|
| 技能准入审核 | 新技能入库资质审查 |
| 13 维度质量评估 | 受众/工作形态/委派阈值/输入/版本/置信度/失败模式等 |
| 3 个法律特有检查 | 越界建议/特权保密/问责缺口 |
| 提示注入扫描 | 隐藏指令检测 |
| 许可证/时效/工具范围门控 | 合规性检查 |

### 输出模板
```
1. 核心结论（Bottom Line）
2. 上下文与审查材料
3. 结构化分析
4. 缺失事实/假设
5. 需律师或主管审查事项
6. 下一步选项
```

### Verdict 等级
| 等级 | 含义 |
|------|------|
| ✅ READY | 全部达标 |
| ⚠️ SOME CONCERN | 1-2 项部分达标 |
| 🔴 MATERIAL CONCERNS | 法律失败模式未处理 |
| ⛔ REFUSE | 含恶意指令 |

### 协作关系
- 上游：接收要审核的技能/工具
- 相关：与法检 Pro 配合进行法律事实核验
- 输出：审核报告给开发团队

## 4. 法检 Pro（法律检索专家）

**文件**：`02-Legal-Knowledge/法律检索专家_法检Pro.md`
**角色**：面向中国法律场景的专业检索专家
**核心理念**："先识场景，再组合能力，最后适配输出"

### 核心能力
| 能力 | 说明 |
|------|------|
| 场景识别与路由 | 命中检索场景，锁定输出标准 |
| 多层法规检索 | 法源位阶扫描、效力验证（7 种状态）、构成要件比对 |
| 类案深度检索 | 三层递进相似度、裁判分歧处理 |
| 场景化输出 | 14 种输出形态、统一引用格式 |
| 核验工作台 | 可点击溯源绑定、HTML 核验报告、二次修复闭环 |

### 覆盖场景
法条确认、事实关联法规、合规汇编、法律适用汇总、模糊定位、类案对比、刑事量刑、企业合规体检等

### 协作关系
- 上游：接收法律检索请求（来自用户/产品通/其他专家）
- 相关：与技信衡配合进行事实核验
- 输出：检索报告/引用列表

## 5. 齐活林（AI 开发团队主理人 / 交付总监）

**文件**：`00-Vision/Software_Development_Team_SOP.md`
**角色**：AI 辅助开发团队的主理人，协调产品经理→架构师→工程师→QA 工作流
**团队**：许清楚（PM）、高见远（架构师）、寇豆码（工程师）、严过关（QA）

### 三种工作流

| 模式 | 适用场景 | 流程 |
|:----:|----------|------|
| ⚡ 快速模式 | ≤10 源文件、单页面 | 工程师直接实现 → QA 验证 |
| 🔧 BugFix | 明确 Bug | 工程师定位修复 → QA 回归 |
| 🏗️ 标准 SOP | 多页面多模块 | PM → 架构师 → 工程师 → QA |

### 核心规则
- 成员禁止直接通信，必须经过主理人中转
- 跳过前序阶段 = 禁止
- 谁的专业产出以谁为准

### 协作关系
- 上游：接收用户开发需求
- 下游：调用产品通(Skill)→架构师→工程师→QA
