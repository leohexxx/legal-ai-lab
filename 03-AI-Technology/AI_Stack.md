# AI 技术路线

## 设计目标

- 输出可追溯：法律信息必须能定位到来源。
- 事实可核对：用户陈述与模型推断分离。
- 流程可控制：关键步骤由确定性工作流约束。
- 行为可评测：建立固定案例集和自动化回归测试。
- 数据可保护：最小采集、访问控制、加密和删除机制。

## 大模型

用于自然语言理解、问题分类、对话引导、结构化提取和自然语言生成。模型不作为法律事实来源。

## RAG

用于从经过筛选和版本管理的法律知识库中检索相关材料。检索结果需携带来源、版本、生效状态和查询日期。

## 向量数据库

用于语义召回，但不应是唯一检索方式。法律条款编号、案号、地域和日期等字段适合结合关键词检索和元数据过滤。

MVP 可优先评估 PostgreSQL + pgvector，以减少基础设施复杂度；只有在规模或检索需求明确后再考虑独立向量数据库。

## Agent 与工作流

首版优先采用受控工作流，而不是高度自治的多 Agent：

1. 场景分类
2. 事实采集
3. 用户确认
4. 知识检索
5. 输出生成
6. 风险检查
7. 转人工判断

## 建议的后续工程栈

- 前端：React / Next.js
- 后端：Python / FastAPI
- 业务数据库：PostgreSQL
- 检索：PostgreSQL 全文检索 + pgvector（先验证）
- AI：支持结构化输出与工具调用的 LLM API
- 观测：请求追踪、提示版本、引用记录、用户反馈和评测日志

具体模型和 API 供应商待基于中文效果、数据政策、延迟、成本与可用性做对比测试后决定。

## Future

- MCP：标准化连接内部知识与工具。
- Multi-Agent：只有在单工作流无法满足分工与评测要求时引入。
- Knowledge Graph：用于主体、事实、条款和证据关系明确且收益可验证的场景。
- Workflow Automation：逐步自动化低风险、可回滚步骤。
