# 法律知识库规划

## 目标

建立面向具体法律问题、可检索、可追溯、可更新和可评测的知识库。知识库不是法规文件的简单堆积，而是将“问题—事实—证据—依据—流程—风险”连接起来。

## 每条知识记录的建议结构

```yaml
id: unique-id
title: 问题标题
problem_type: 问题类型
legal_domain: 法律领域
jurisdiction: 适用地区
effective_date: 生效日期
status: 现行/失效/待核验
facts_required: 需要确认的事实
legal_basis:
  - 名称、条款、来源链接、发布日期、查询日期
related_cases:
  - 案号、法院、裁判日期、来源、参考边界
evidence_required: 需要的证据
procedure: 处理流程
risks: 风险与时效提示
lawyer_type: 推荐律师类型
review:
  reviewer: 审核人
  reviewed_at: 审核日期
```

## 质量规则

- 优先使用权威、稳定、可核验来源。
- 保存来源链接、版本、生效状态和查询日期。
- 法规、案例、解释性内容分开存储。
- 案例仅作为参考，不将个案结果机械套用。
- 内容变更应保留版本记录并触发回归评测。
- 进入用户输出前应经过法律专业人士抽样或专项审核。

## 初始范围

先建立劳动法领域的欠薪主题知识集；其他领域文档作为研究入口，不在首个 MVP 中同时建设。
