# 欠薪案件信息采集规范

## 目的

定义“AI 劳动纠纷助手”欠薪场景需要采集的最小信息。系统应分轮提问，不应把本文件直接展示为冗长表单。

## 采集原则

- 先收集解决问题所必需的信息。
- 允许回答“不知道”“不确定”或“暂不提供”。
- 说明敏感信息的用途，默认不采集完整身份证号、银行卡号和无关第三方信息。
- 区分用户原始陈述、系统结构化结果和系统推断。
- 生成分析前要求用户确认核心事实。

## 字段定义

### 1. 用户目标

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `primary_goal` | 枚举/文本 | 是 | 希望获得工资、了解流程、整理材料或咨询律师 |
| `urgent_concern` | 文本 | 否 | 用户认为最紧急的事项 |

### 2. 用工主体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `employer_name` | 文本 | 是 | 可先用简称，导出前再核对全称 |
| `work_location` | 地区 | 是 | 至少到城市，用于后续适用范围和办事路径判断 |
| `contract_entity` | 文本 | 否 | 劳动合同记载主体 |
| `salary_payer` | 文本 | 否 | 实际支付工资的主体 |
| `work_manager` | 文本 | 否 | 实际安排工作的主体或部门 |
| `entity_mismatch` | 布尔/未知 | 系统生成 | 合同、发薪与实际管理主体是否可能不一致 |

### 3. 劳动关系时间

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `start_date` | 日期/约略日期 | 是 | 入职或实际开始工作时间 |
| `employment_status` | 枚举 | 是 | 在职、已离职、被停工或不确定 |
| `end_date` | 日期/约略日期 | 条件必填 | 已离职时采集 |
| `departure_type` | 枚举/文本 | 否 | 主动离职、被解除、协商或其他 |

### 4. 合同与工资约定

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `written_contract` | 是/否/未知 | 是 | 是否签订书面劳动合同 |
| `contract_available` | 是/否 | 否 | 是否还能提供合同 |
| `agreed_salary` | 金额/文本 | 是 | 约定工资及计薪方式 |
| `salary_components` | 列表 | 否 | 基本工资、提成、奖金、补贴等 |
| `pay_cycle` | 文本 | 否 | 约定发薪日期或周期 |

### 5. 欠薪明细

欠薪应按期间逐条记录，不能只保存一个总金额。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `period` | 月份/日期区间 | 是 | 工资对应期间 |
| `amount_expected` | 金额/未知 | 是 | 应付金额或计算方式 |
| `amount_paid` | 金额 | 是 | 已支付金额，未支付记为 0 |
| `amount_claimed` | 金额/待计算 | 系统生成 | 用户主张的差额 |
| `calculation_basis` | 文本 | 否 | 合同、工资条、考勤或历史发薪记录 |
| `disputed_by_employer` | 是/否/未知 | 否 | 单位是否对金额或事实提出异议 |

### 6. 已有证据

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `contracts` | 列表 | 否 | 劳动合同、协议等 |
| `payment_records` | 列表 | 否 | 银行流水、工资条、转账记录 |
| `attendance_records` | 列表 | 否 | 考勤、排班、工时记录 |
| `work_records` | 列表 | 否 | 工牌、邮件、工作成果、系统记录 |
| `communications` | 列表 | 否 | 与欠薪有关的聊天、邮件或通知 |
| `witnesses` | 列表 | 否 | 仅记录是否存在及与事件关系，不收集无关隐私 |

每项证据还应记录：是否持有、覆盖时间、是否完整、原件位置以及待补充事项。

### 7. 已采取行动

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `employer_contacted` | 是/否 | 是 | 是否与单位沟通 |
| `employer_response` | 文本 | 否 | 单位主要答复 |
| `external_actions` | 列表 | 否 | 咨询、投诉、调解、仲裁或诉讼等 |
| `documents_received` | 列表 | 否 | 已收到的通知或法律文书 |
| `known_deadlines` | 列表 | 否 | 用户已知的日期或期限；系统不得擅自推定 |

## 对话阶段

1. **范围确认：** 判断是否属于欠薪主场景。
2. **主体与时间：** 识别谁用工、在哪里工作、何时开始和结束。
3. **金额拆分：** 按期间核对约定、应付与已付。
4. **证据盘点：** 标记已有、缺失和待确认材料。
5. **行动记录：** 了解已沟通或已进入的程序。
6. **事实确认：** 展示摘要，让用户逐项修改或确认。
7. **后续处理：** 在检索可靠资料后，生成带来源和边界的说明。

## 输出前校验

- 欠薪期间是否明确。
- 金额是否有计算依据；无依据时是否标记“待计算”。
- 用工主体是否可能不一致。
- 日期冲突是否向用户重新确认。
- 是否把推断误写为用户已确认事实。
- 是否存在需优先转人工处理的紧急或复杂情况。
