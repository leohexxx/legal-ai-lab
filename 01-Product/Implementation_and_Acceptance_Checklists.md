## 1. 需求进入开发前

### 1.1 用户问题

- [ ] 能用一句话说明目标用户是谁。
- [ ] 能用一句话说明用户要完成的任务。
- [ ] 已记录用户当前如何解决问题。
- [ ] 已说明用户为什么可能放弃。
- [ ] 已区分用户想了解信息、准备材料、启动程序还是找律师。
- [ ] 已识别移动端、低数字能力和情绪压力场景。
- [ ] 已列出最容易被误解的法律术语。
- [ ] 已定义完成后的可见交付物。
- [ ] 已定义不属于本功能的情况。
- [ ] 已定义何时必须转人工。

### 1.2 法律边界

- [ ] 已说明功能提供法律信息还是正式法律服务。
- [ ] 已确定适用国家、省、市、区县或法域。
- [ ] 已记录规则的生效和失效时间。
- [ ] 已识别主管机关和程序阶段。
- [ ] 已区分一般规则、例外和地方差异。
- [ ] 已列出会改变结论的关键事实。
- [ ] 已列出不能由 AI 自动判断的事项。
- [ ] 已定义律师审核要求。
- [ ] 已审查产品名称和营销文案不会暗示结果保证。
- [ ] 已定义用户看到的免责声明和限制。

### 1.3 数据与隐私

- [ ] 每个字段都有明确用途。
- [ ] 不收集与任务无关的身份证号、银行卡号等信息。
- [ ] 已确定字段是必填、选填还是可以回答不知道。
- [ ] 已确定数据保留时间。
- [ ] 已确定是否用于模型训练。
- [ ] 已确定访问角色。
- [ ] 已确定导出和删除方式。
- [ ] 已确定文件遮盖提示。
- [ ] 已完成数据流图。
- [ ] 已完成威胁和滥用场景清单。

### 1.4 成功指标

- [ ] 已定义用户完成率。
- [ ] 已定义关键事实完整率。
- [ ] 已定义引用可追溯率。
- [ ] 已定义严重错误。
- [ ] 已定义性能目标。
- [ ] 已定义无障碍目标。
- [ ] 已定义隐私和删除目标。
- [ ] 已有基线或说明如何建立基线。
- [ ] 指标不依赖采集案情正文。
- [ ] 已定义发布后停止或回滚阈值。

## 8. 胜率和结果分析上线门槛

以下每一项都必须满足：

### 8.1 结果定义

- [ ] 定义是请求是否支持、支持比例、金额、调解、仲裁、诉讼还是执行。
- [ ] 不把不同结果合并成一个“胜”。
- [ ] 结果字段可从数据稳定取得。
- [ ] 结果定义经法律人员审核。

### 8.2 数据

- [ ] 数据来源合法。
- [ ] 数据覆盖未公开或非诉结果的局限已说明。
- [ ] 样本去标识化。

## 11. 测试场景清单

### 11.1 正常路径

- [ ] 不知道是否签合同。
- [ ] 地区不明确。

### 11.3 矛盾

- [ ] 用户两次提供不同工资。

- [ ] 合同主体与工资支付主体不同。
- [ ] 用户说已支付又说未支付。
- [ ] 文件日期冲突。
- [ ] 公司承认部分金额但否认其他金额。

- [ ] 劳务派遣。
- [ ] 群体性欠薪。

- [ ] 社保与解除混合。
- [ ] 已进入诉讼。
- [ ] 可能超过期限。
- [ ] 不属于当前支持地区。

### 11.5 系统失败

- [ ] 保存超时。
- [ ] 文件上传中断。
- [ ] 文件解析失败。
- [ ] 检索无结果。

- [ ] 后台任务重复。
- [ ] 用户同时在两个设备修改。
- [ ] 删除任务部分失败。

### 11.6 对抗与滥用

- [ ] 用户要求编造法条。

- [ ] 用户要求保证胜诉。

- [ ] 超大文件或大量重复请求。
