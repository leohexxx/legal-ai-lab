# Legal AI Lab 前端需求规格

> - 版本：v1.0
> - 日期：2026-07-27
> - 第一发布范围：欠薪用户端闭环
> - 长期范围：通用法律入口、专业领域模块、律师端、知识运营端和结果分析

## 1. 文档目标

本文把产品战略和全球竞品研究转成可设计、可开发、可测试的前端需求。页面名称、状态、数据和验收条件均用于指导原型、接口和开发任务。

本文不是视觉稿。字体、颜色、品牌和高保真组件规范应在交互原型稳定后形成独立设计系统。

## 2. 前端必须解决的问题

用户不是为了“和 AI 聊天”而来。用户需要完成五件事：

1. 确认系统能否处理自己的问题；
2. 把零散描述变成可核对的案件事实；
3. 知道拥有哪些证据、缺少哪些证据；
4. 看懂适用规则、风险和下一步；
5. 保存、导出或交给律师继续处理。

因此主产品是案件工作台，对话只是采集和解释方式之一。

## 3. 产品体验原则

### 3.1 任务优先

- 首页使用“描述问题”“选择常见问题”“继续已有案件”作为主入口；
- 不用模型名称、参数和技术名词占据首屏；
- 每一步告诉用户当前任务、为什么要问、完成后得到什么。

### 3.2 事实优先

所有案件内容分为：

| 状态 | 含义 | 前端表现 |
|---|---|---|
| 用户已确认 | 用户明确确认 | 实色标签，可用于后续分析 |
| 用户陈述、待确认 | 已记录但未确认 | 提示色标签，要求确认 |
| AI 推断 | 系统从材料或上下文推测 | 单独区域，不写入已确认事实 |
| 外部来源 | 法规、案例或官方材料 | 来源卡和原文链接 |
| 律师意见 | 执业律师提供 | 显示律师身份、时间和范围 |
| 存在矛盾 | 两个信息不能同时成立 | 警告状态，阻止确定性结论 |

### 3.3 来源优先

- 每条法律信息旁边都能打开来源；
- 显示发布机关、文件名称、条款、效力、适用地区、查询日期；
- 失效、修订、地区不匹配和仅供参考必须显著；
- 不把模型生成文字伪装成法规原文。

### 3.4 渐进披露

- 每屏只要求完成一个清楚任务；
- 默认展示摘要，需要时展开细节；
- 复杂法律说明先给白话结论，再给条件、例外和原文；
- 重要风险不能藏在折叠区。

### 3.5 可恢复

- 用户可保存草稿、退出后继续；
- 每个异步任务显示状态；
- 失败时保留已经输入的内容；
- 用户可以修改事实并重新生成受影响结果；
- 删除和撤回授权有明确结果。

### 3.6 移动端优先

劳动者可能只使用手机。P0 主流程必须在 360px 宽度完成，文件预览和复杂表格可以提供移动端简化视图。

## 5. 用户角色与权限

| 角色 | 查看 | 编辑 | 导出 | 转交 | 审核 | 管理 |
|---|---|---|---|---|---|---|
| 未登录访客 | 临时草稿 | 临时草稿 | 否 | 否 | 否 | 否 |
| 已登录用户 | 自己案件 | 自己事实和文件 | 自己案件 | 可授权 | 否 | 自己的数据设置 |
| 被邀请共同处理人 | 被授权部分 | 按授权 | 按授权 | 否 | 否 | 否 |
| 律师 | 已接受案件 | 律师意见和批注 | 服务范围内 | 可退回补充 | 专业审核 | 否 |
| 知识编辑 | 公共知识 | 草稿知识 | 知识报告 | 否 | 否 | 否 |
| 知识审核员 | 公共和待审知识 | 审核意见 | 审核记录 | 否 | 是 | 发布权限按角色 |
| 机构管理员 | 机构案件 | 分配和状态 | 机构范围 | 分配 | 运营审核 | 机构配置 |

权限采用最小授权。律师不能因为属于合作机构就自动读取全部用户案件。

## 6. 核心用户旅程

### 6.1 新用户欠薪旅程

```text
首页描述“公司两个月没有发工资”
  -> 系统识别可能为欠薪
  -> 用户确认地区和劳动关系相关信息
  -> 系统按模块追问
  -> 用户查看并修改事实摘要
  -> 系统生成工资差额、时间线和证据清单
  -> 系统检索法律依据
  -> 系统展示风险和下一步
  -> 用户保存、导出或授权律师接收
```

### 6.2 信息不足旅程

```text
用户只说“老板欠我两万多”
  -> 金额标记为估算
  -> 引导按月份重建应付和实付
  -> 仍无法确认时保留待核实状态
  -> 输出缺失项，不输出确定欠款
```

### 6.3 可能不属于劳动关系

```text
用户说“接项目后对方不付尾款”
  -> 询问管理、考勤、支付、工具和合同履行方式
  -> 不能确定时标记待分类
  -> 不强行进入欠薪规则
  -> 提供一般材料整理或建议人工核验
```

### 6.4 高风险转人工

```text
识别人身安全、群体性事件、主体复杂、期限紧迫或重大矛盾
  -> 显示紧急提示
  -> 停止不适当的自动结论
  -> 展示可选人工渠道
  -> 用户预览并授权转交内容
```

## 8. 普通用户端详细页面需求

### U01：首页与任务入口

**目的：** 让用户在 10 秒内知道产品能帮什么，并开始描述问题。

**核心组件：**

- 一句话价值说明；
- 自由描述输入框；
- 常见问题卡片；
- “继续已有案件”；
- 当前支持领域；
- 服务边界简述；
- 隐私入口；
- 紧急情况提示入口。

**交互：**

- 输入支持文本，语音作为后续增强；
- 未输入时提供示例，但示例不能暗示结果；
- 常见问题卡只负责进入流程，不直接给固定答案；
- 提交后创建临时案件 ID。

**状态：**

- 默认；
- 输入中；
- 正在识别；
- 无法识别；
- 可能紧急；
- 服务不可用；
- 恢复上次草稿。

**验收：**

- 360px 宽度可输入并提交；
- 不登录也可以完成初始描述；
- 不在首屏要求手机号；
- 无法识别时不编造领域；
- 显示当前只深度支持哪些领域。

### U02：服务边界与隐私同意

**目的：** 在采集具体案件信息前取得清楚、可记录的同意。

**核心内容：**

- 产品提供法律信息和流程辅助；
- AI 不替代律师；
- 哪些数据会被处理；
- 为什么需要这些数据；
- 文件上传前遮盖无关敏感信息；
- 保留时间；
- 是否用于模型训练；
- 用户导出、删除和撤回授权的方法；
- 紧急事项不应依赖本产品。

**交互：**

- 关键条款分项确认，不使用默认勾选；
- 隐私全文可打开；
- 记录版本、时间和同意范围；
- 拒绝后允许退出或只浏览公开信息。

**验收：**

- 未同意不进入案件采集；
- 同意记录可查询；
- 条款更新后重新确认；
- 不把营销同意和必要服务同意捆绑。

### U03：领域、地区和目标确认

**目的：** 确定使用哪个专业模块和后续程序信息。

**字段：**

- 问题领域；
- 案件发生地或工作地；
- 用人单位所在地；
- 用户当前所在地；
- 用户目标；
- 是否已经投诉、仲裁或诉讼；
- 是否存在紧急事项。

**交互：**

- 系统给出建议领域，用户可以修改；
- 地区使用省、市、区县三级选择和搜索；
- 解释为什么地区会影响规则和主管机关；
- 多问题时允许选择主问题和相关问题。

**验收：**

- 地区不明确时允许继续，但后续结果标记限制；
- 非支持领域进入安全降级；
- 多领域问题不会一次生成综合确定结论；
- 已进入程序的案件提高转人工优先级。

### U04：引导式事实采集

**目的：** 以用户能理解的语言收集最小必要事实。

**欠薪模块步骤：**

1. 用工主体和工作地点；
2. 入职、离职和当前状态；
3. 合同和实际管理关系；
4. 工资约定和构成；
5. 每期应付、实付和差额；
6. 证据；
7. 已采取行动；
8. 用户目标和紧急事项。

**页面结构：**

- 顶部进度；
- 当前问题；
- 为什么需要；
- 输入控件；
- “不知道/不确定”；
- 保存并退出；
- 上一步；
- 本轮已记录摘要。

**规则：**

- 每屏不超过 3 个强相关问题；
- 金额和日期提供格式辅助；
- 不把空值当作否；
- “不知道”生成待补任务；
- 逻辑分支基于已回答字段；
- 用户可以回到任何已完成步骤。

**验收：**

- 刷新或网络失败后不丢失已保存内容；
- 必填只针对当前分析真正必要的字段；
- 用户不知道公司全名时仍可保存；
- 合同主体、工资支付主体和实际管理主体分别采集；
- 工资按期间记录，不只收总额；
- 提成、加班和扣款可作为不同工资组成。

### U05：事实摘要确认

**目的：** 在检索和生成行动建议前锁定本次分析使用的事实版本。

**区域：**

- 已确认事实；
- 待确认；
- 系统推断；
- 矛盾；
- 缺失但重要；
- 用户修改记录。

**交互：**

- 每条事实单独编辑；
- 一键确认全部仅在没有矛盾时可用；
- 修改后显示受影响的时间线、证据和分析；
- 矛盾必须选择、解释或保留争议；
- 生成 `fact_version`。

**验收：**

- 未确认事实不进入确定性陈述；
- AI 推断不能被系统自动转成已确认；
- 事实修改后旧分析标为过期；
- 用户可以查看历史版本。

### U06：案件工作台总览

**目的：** 一屏理解案件当前状态和下一步。

**区域：**

- 案件名称和状态；
- 主体；
- 主请求；
- 核心金额；
- 关键日期；
- 准备度；
- 最高风险；
- 待办；
- 最近更新；
- 报告和律师帮助入口。

**状态机：**

```text
草稿
  -> 待确认事实
  -> 分析中
  -> 已生成
  -> 待补材料
  -> 准备行动
  -> 已转律师
  -> 处理中
  -> 已完成
  -> 已归档/已删除
```

**验收：**

- 状态名称使用用户语言；
- 最高风险不只用颜色表达；
- 所有卡片能进入明细；
- 案件编号、更新时间和数据控制入口可见。

### U07：欠薪金额明细

**目的：** 让用户和律师核对“哪一期、应付多少、实付多少、差多少”。

**字段：**

- 工资期间；
- 应付日期；
- 固定工资；
- 提成；
- 加班；
- 奖金；
- 津贴；
- 扣款；
- 应付总额；
- 实付金额；
- 差额；
- 金额状态；
- 依据文件；
- 备注。

**状态：**

- 已确认；
- 估算；
- 待核实；
- 双方争议；
- 计算规则缺失。

**交互：**

- 新增期间；
- 复制上期工资结构；
- 上传工资条或流水关联；
- 修改金额后自动重算差额；
- 显示公式；
- 导出明细。

**验收：**

- 金额使用高精度十进制，不使用浮点展示误差；
- 总额必须可以追溯到每期；
- 估算值不能显示为确定请求；
- 争议提成与固定工资分开展示；
- 修改任何构成后总额实时更新。

### U08：时间线

**目的：** 按时间查看劳动关系和争议发展。

**事件类型：**

- 入职；
- 合同签订或变更；
- 工资约定；
- 工资应付；
- 实际支付；
- 催讨；
- 公司回复；
- 离职或解除；
- 投诉；
- 仲裁；
- 诉讼；
- 材料补充；
- 律师意见。

**交互：**

- 列表和时间轴切换；
- 过滤事件类型；
- 每个事件关联主体、事实和证据；
- 未知日期支持范围；
- 用户可以新增和编辑。

**验收：**

- 同日事件顺序不确定时不强行排序；
- 估算日期有明显标记；
- 删除事件前说明受影响内容；
- 导出报告顺序与页面一致。

### U09：证据中心

**目的：** 管理已有、缺失、矛盾和建议补充的证据。

**证据类别：**

- 劳动合同；
- 工资条；
- 银行流水；
- 考勤；
- 聊天和邮件；
- 工作成果；
- 录音录像；
- 公司通知；
- 投诉或程序材料；
- 身份和主体证明；
- 其他。

**每项字段：**

- 名称；
- 类型；
- 证明目的；
- 关联事实；
- 来源；
- 时间；
- 是否原件；
- 完整性；
- 隐私风险；
- 当前状态；
- 用户说明；
- AI 提取结果；
- 律师审核结果。

**交互：**

- 上传；
- 拍照；
- 手工登记但暂不上传；
- 预览；
- 遮盖提示；
- 关联事实；
- 标记缺失；
- 下载和删除；
- 查看访问记录。

**验收：**

- 上传前显示允许格式、大小和隐私提示；
- 文件扫描和解析中有独立状态；
- AI 提取与原文并排；
- 文件解析失败不删除原件；
- 用户删除后生成可验证状态；
- 证据“存在”不等于“足以证明”，二者分开。

### U10：法律依据与来源

**目的：** 让用户理解规则，同时让专业人员能核验。

**来源卡字段：**

- 白话标题；
- 适用结论；
- 必要条件；
- 例外；
- 文件名称；
- 发布机关；
- 条款；
- 现行有效状态；
- 适用地区；
- 生效时间；
- 查询日期；
- 原文链接；
- 与案件哪些已确认事实相关；
- 限制和待核实项。

**交互：**

- 摘要和原文切换；
- 打开官方来源；
- 复制引用；
- 反馈不适用或打不开；
- 查看修订或替代关系；
- 查看系统为何引用。

**验收：**

- 每条法律结论至少一个来源；
- 原文引用和模型解释视觉区分；
- 不适用地区和失效来源不能作为当前依据；
- 来源打不开时保留元数据并提示；
- 用户可看到查询日期。

### U11：风险与案件准备度

**目的：** 在没有可靠胜率数据时提供可操作的案件分析。

**维度：**

- 事实完整度；
- 证据充分度；
- 主体明确度；
- 金额明确度；
- 请求完整度；
- 期限风险；
- 管辖风险；
- 程序状态；
- 事实矛盾；
- 待核实关键因素。

**每个维度显示：**

- 当前等级；
- 造成等级的具体因素；
- 可以采取的改进动作；
- 哪些因素无法由用户自行解决；
- 数据更新时间。

**禁止：**

- P0 显示胜率；
- 只显示红黄绿不解释；
- 把缺失数据计算为低胜率；
- 用“高风险”吓迫用户购买服务。

**验收：**

- 每个风险可追溯到事实、证据或规则；
- 用户能知道下一步怎么改善；
- 更新材料后重新计算；
- 结果变化有记录。

### U12：行动方案与任务

**目的：** 把分析转成有顺序、有材料、有期限的行动。

**每个行动包含：**

- 行动名称；
- 适用前提；
- 目标；
- 优先级；
- 建议时间；
- 主管机关或对象；
- 所需材料；
- 可能结果；
- 成本和费用说明；
- 风险；
- 是否建议律师；
- 完成状态。

**典型行动：**

- 补齐工资明细；
- 保存和导出证据；
- 书面催讨；
- 劳动监察投诉；
- 调解；
- 劳动仲裁；
- 诉讼；
- 咨询律师。

**验收：**

- 行动是可选方案，不写成强制命令；
- 程序路径和条件匹配用户地区；
- 已经完成的行动不会重复建议；
- 高风险行动提示律师核验；
- 用户可设置完成状态和提醒。

### U13：报告、导出和分享

**报告结构：**

1. 服务边界；
2. 用户确认事实；
3. 待核实和争议事实；
4. 主体和请求；
5. 金额明细；
6. 时间线；
7. 证据；
8. 法律依据；
9. 风险；
10. 行动方案；
11. 来源和生成信息。

**格式：**

- 屏幕阅读；
- PDF；
- Markdown；
- 后续可增加 Word；
- 结构化案件包。

**分享：**

- 下载；
- 短时分享链接；
- 授权律师；
- 撤回链接；
- 分享范围预览。

**验收：**

- 报告显示生成时间、事实版本和知识版本；
- 导出与页面事实一致；
- 分享默认关闭；
- 分享链接可过期和撤回；
- 不在文件名暴露敏感信息。

### U14：历史案件

**功能：**

- 案件列表；
- 状态、领域、地区和更新时间；
- 搜索；
- 筛选；
- 继续；
- 复制为新案件；
- 归档；
- 删除。

**验收：**

- 默认只显示用户自己的案件；
- 已删除案件不出现在搜索；
- 归档和删除含义清楚；
- 用户能查看最近访问和更新。

### U15：数据、授权和删除

**功能：**

- 查看已同意条款；
- 查看数据类别；
- 下载数据；
- 查看分享和律师授权；
- 撤回授权；
- 删除文件；
- 删除案件；
- 删除账户；
- 查看删除进度；
- 联系隐私支持。

**验收：**

- 撤回后新访问立即失效；
- 删除任务有请求时间和完成状态；
- 法定必须保留的数据说明原因和期限；
- 用户可以只删除文件而不删除案件；
- 高风险动作要求再次确认。

### U16：律师帮助和转交

**功能：**

- 说明为什么建议律师；
- 选择服务类型；
- 地区和领域匹配；
- 律师或机构资质信息；
- 费用范围；
- 可预约时间；
- 转交内容预览；
- 用户删减和授权；
- 接收状态；
- 后续沟通。

**验收：**

- 不承诺结果；
- 不按“胜率”排序律师；
- 未授权不能转交；
- 用户可以撤回尚未接收的转交；
- 律师接收后显示服务范围和责任主体。

## 9. 律师端详细需求

### L01：律师案件队列

**列表字段：**

- 案件编号；
- 领域；
- 地区；
- 用户目标；
- 金额；
- 紧急等级；
- 关键期限；
- 资料完整度；
- 转交时间；
- 冲突检查状态；
- 当前服务状态。

**操作：**

- 预览匿名摘要；
- 接受；
- 拒绝并选择原因；
- 请求冲突检查；
- 分配团队成员；
- 设置优先级。

### L02：律师案件审阅

**布局：**

- 左侧案件目录；
- 中间事实、时间线或文件；
- 右侧 AI 分析、来源和批注；
- 顶部状态和任务；
- 底部用户沟通。

**要求：**

- AI 输出不可覆盖用户原始材料；
- 律师可逐条确认、修改或拒绝；
- 律师意见独立版本；
- 修改记录含人员、时间和原因；
- 关键期限需要明确确认。

### L03：证据和来源对照

- 点击事实查看支持证据；
- 点击证据查看支持哪些事实；
- 点击结论查看法规和案例；
- 标记充分、部分、无支持、矛盾；
- 生成缺失材料请求；
- 句子级跳转原文件。

### L04：补充请求和律师意见

- 使用结构化问题向用户补充；
- 设置截止时间；
- 用户回复自动关联案件；
- 律师形成意见草稿；
- 正式法律意见必须经过明确发布操作；
- 用户端区分 AI 信息和律师意见。

## 10. 知识运营端详细需求

### K01：来源和知识卡列表

支持：

- 类型、领域、地区、机关、效力、审核状态筛选；
- 来源和知识卡关联；
- 内容哈希变化提示；
- 待失效和待复核提醒；

- 结构化知识卡；
- 字段校验；
- 引用位置；
- 修改差异；
- 审核意见；
- 相关评测。

### K03：版本、关系和发布

- 草稿、待审、批准、发布、撤回状态；
- 生效和失效时间；
- supersedes / superseded_by；
- 回滚；
- 发布影响分析；
- 受影响领域和测试；
- 发布审批记录。

## 11. 类似案例与结果分析界面

### 11.1 P2 类似案例

**筛选条件：**

- 地区；
- 机构或法院；
- 时间范围；
- 案由；
- 请求类型；
- 程序阶段；
- 劳动关系状态；
- 证据状态；
- 主体类型；
- 金额区间。

**结果字段：**

- 相似理由；
- 事实差异；
- 证据差异；
- 请求；
- 结果；
- 金额；
- 周期；
- 来源；
- 权威和公开范围；
- 是否可用于统计。

### 11.2 P3 概率输出最低要求

任何概率页面必须同时展示：

- “胜”的具体定义；
- 输入条件；
- 样本量；
- 数据时间；
- 地区；
- 程序阶段；
- 置信区间；
- 模型版本；
- 校准结果；
- 已知缺失；
- 不构成保证；
- 原始样本或可核验摘要。

如果这些信息缺失，前端不渲染概率，只显示“数据不足以形成可靠概率”。

## 15. 页面通用状态

每个页面必须设计：

- 首次加载；
- 已有数据；
- 空状态；
- 局部加载；
- 后台任务；
- 网络超时；
- 服务错误；
- 权限不足；
- 数据已删除；
- 版本过期；
- 部分成功；
- 离线或断网；
- 会话过期；
- 数据冲突；
- 不支持的地区或领域；
- 需要人工处理。

错误提示必须包含：

1. 发生了什么；
2. 哪些数据已保存；
3. 用户现在能做什么；
4. 是否可以重试；
5. 必要时的支持渠道。

## 16. 响应式要求

| 宽度 | 主要布局 |
|---|---|
| 360–767px | 单列，底部主操作，表格转卡片，侧栏转抽屉 |
| 768–1199px | 双栏，可折叠目录和来源面板 |
| 1200px 以上 | 三栏案件审阅，固定目录、内容和证据/来源 |

移动端要求：

- 主要按钮可触达；
- 不依赖鼠标悬停；
- 文件上传支持拍照；
- 时间线和金额表使用卡片；
- 长法律原文独立阅读页；
- 不在小屏同时显示三个滚动区域。

## 17. 无障碍要求

- 达到 WCAG 2.2 AA 目标；
- 键盘可完成所有关键流程；
- 焦点顺序符合阅读顺序；
- 状态不只使用颜色；
- 表单有可关联标签和错误；
- 动态更新使用适当通知；
- 对话和时间线能被屏幕阅读器理解；
- PDF 之外提供可访问的 HTML 报告；
- 文本缩放 200% 仍可使用；
- 触控目标至少满足可用尺寸。

## 18. 隐私与安全要求

- 敏感字段默认不显示完整值；
- 文件链接短时有效；
- 分享链接默认关闭；
- 从 URL、日志和分析埋点中排除案情正文；
- 剪贴板、下载和打印提供提醒；
- 多次错误登录触发保护；
- 权限变更立即生效；
- 用户可以查看哪些律师或人员访问过案件；
- 前端不持久化不必要的原始文件内容；
- 调试日志不得包含案件事实、证件或联系方式；
- 所有外部跳转说明目的。

## 19. 埋点与指标

埋点仅记录产品事件和匿名化标识，不记录案情正文。

| 事件 | 目的 |
|---|---|
| matter_started | 新案件开始 |
| domain_suggested / corrected | 领域路由质量 |
| intake_step_completed | 各步骤完成率 |
| unknown_selected | 用户无法回答的字段 |
| fact_edited / confirmed | 事实确认质量 |
| evidence_registered / uploaded | 证据准备情况 |
| source_opened | 来源是否被核验 |
| risk_action_clicked | 风险是否可操作 |
| action_marked_complete | 行动方案价值 |
| report_generated / downloaded | 交付物使用 |
| handoff_started / authorized / accepted | 律师闭环 |
| deletion_requested / completed | 数据控制 |
| error_shown / retry_succeeded | 可靠性 |

## 20. 前端发布切片

### Slice 1：可点击原型

- U01 至 U06；
- 使用合成案件；
- 验证信息架构和用户理解；
- 不接真实文件和模型。

### Slice 2：欠薪事实闭环

- U03 至 U08；
- 接入案件和事实接口；
- 支持保存、继续和确认；
- 使用固定规则生成演示结果。

### Slice 3：证据、来源和风险

- U09 至 U12；
- 接入知识库和异步分析；
- 支持文件登记和来源原文；
- 建立回归测试。

### Slice 4：交付和数据控制

- U13 至 U15；
- 报告、历史、导出、删除和审计；
- 完成移动端和无障碍验收。

### Slice 5：律师承接

- U16、L01 至 L04；
- 模拟或真实受控合作；
- 验证上下文连续性和权限。

## 21. 前端完成定义

一个页面只有同时满足以下条件才算完成：

- 用户任务和成功结果明确；
- 数据字段和来源明确；
- 所有状态已设计；
- 错误和恢复已实现；
- 360px 移动端可用；
- 键盘和屏幕阅读器基本可用；
- 敏感信息处理已审查；
- 分析埋点不包含案情正文；
- 接口错误不会导致事实丢失；
- 验收测试通过；
- 文案经过法律边界审核；
- 相关文档和截图已更新。
